## P0 — data-loss and safety bugs (fix before anything else)

All verified in source.

1. **Profile zip import can write anywhere in the TF2 install.** `zip.rs:328/352`, `profile.rs:881`, `switch.rs:176` gate only with `is_forbidden_rel_path` (4 filenames + `tf2_*.vpk`). A zip listing `files/bin/x64/client.dll` or `files/tf/cfg/user/autoexec.cfg` imports cleanly and the next switch writes it into the live tree. The correct allowlist predicate already exists: `apply.rs:51 is_file_safe_rel_path` (`tf/cfg/` or `tf/custom/`, rejects `tf/cfg/user/`). Use it in all four places and pre-flight the whole manifest before the Remove step of a switch. Regression test required.
2. **A failed switch destroys the old profile.** `switch.rs:100-137` removes the old profile's live files, then writes the new ones, then flips `activeProfileId`. Any mid-write failure leaves a half-replaced tree with the index still on the old profile; the next boot's absorb ingests the mixed tree into the old profile. Fix: validate every source exists before Remove; write `dest.part` + rename; on failure after Remove, clear `activeProfileId` and surface "mid-switch, re-apply".
3. **HUD schema `#base` option wipes the target file.** `hud_apply.rs:344-350 write_base_file` replaces the whole `.res` (e.g. rayshud `mainmenuoverride.res`) with one `#base` line. `split_base_lines` two functions away is the fix. Also `hud_apply.rs:321-324` turns non-UTF-8 (UTF-16 BOM) `.res` files into `""` and rewrites them as only the patch.
4. **Absorb never fires if execs starts while TF2 is running.** `App.tsx:264` seeds `lastRunning=false` and never reconciles with the boot lock read; the poller's first emit precedes listener registration. Quit → single `false` event → guard fails → drift never absorbed → next switch exact-replaces over it. Fix: `useRef<boolean|null>` written by both boot and listener; treat `!== false → false` as a quit.
5. **No write serialization between auto-absorb and settings writes.** Zero `tauri::State`/`Mutex` in the crate; `absorbOwned` fires outside `SettingsHost`'s busy queue; every write is an unsynchronized read-modify-write of `index.json`+`manifest.json`. Add a `tokio::sync::Mutex<()>` write gate in managed state, taken by every library/live-surface command.
6. **Non-atomic JSON writes, O(n²) per save.** `profile.rs:935 write_json` is bare `fs::write`; `put_exclusive_file_from_path_to` rewrites index+manifest per file. A 3,000-file HUD save = ~6,000 non-atomic rewrites; a crash mid-write makes the entire library unloadable. Fix: temp+rename, and a batch API that writes manifest/index once.
7. **`localconfig.vdf` rewritten non-atomically through a lossy serializer.** `launch.rs:155`; `vdf.rs:328` has no `[$WIN32]` conditional support, so any conditional shifts every following key. Same parser corrupts HUD `.res` merges (`hud_apply.rs:326-339`). Fix: atomic write + one-shot backup; parse/re-emit conditionals or refuse to write when re-parse(serialize(x)) ≠ x.
8. **Stale `reload()` writes profile A's files into profile B.** `SettingsHost.tsx:228-266`: `cancelled` guards only `onError`; `setDetail/setFiles/setComfig/setLaunch` are unguarded. The HUD path (`:277-309`) already uses a request token — copy it.
9. **Preloader: run-lock TOCTOU across an 81 MB download.** `commands.rs:893` checks `refuse_if_running()` then downloads for up to 600 s, then patches official VPKs. Core `apply_preloader_selection`/`revert_preloader`/`set_gameinfo_bypass` carry no lock of their own. Move the lock into core (as `viewmodel.rs:200` does) and re-check right before the first write.
10. **Preloader: `gameinfo.txt` toggle corrupts lines with trailing comments.** `preloader.rs:122-163` treats any `//` on the line as "commented"; revert drains the first `//` found, producing `type multiplayer_only  execs`. Backup `gameinfo.original.txt` is write-only and never refreshed after a TF2 update. Locate `type` first; only `//` before it counts; expose the backup as a repair path.
11. **Removing a viewmodel pack deletes the preload cfg the mods preloader needs.** `viewmodel.rs:295-300, 543-554` remove the preload unconditionally; only the mods→viewmodel direction of the shared-ownership rule exists. This recreates the 2026-08-31 "installed but nothing works" failure. Add `preloader::preload_is_wanted()` and gate both removal sites.
12. **`remove_crosshairs_to` deletes a live pack without the write lock.** `crosshair.rs:353-377`: `remove_live_pack` runs unconditionally; the only `refuse_if_running` sits inside `if !previous.is_empty()`.
13. **Viewmodel build is Windows-only.** `commands.rs:677` hardcodes `bin/studiomdl.exe`; core's error text too. Product is Windows+Linux.
14. **Release workflow can publish a half-populated `latest.json`.** `release.yml`: `fail-fast: false` + `releaseDraft: false` + `includeUpdaterJson`. One platform failing ships a live updater manifest missing the other. Draft first, verify both platforms, then publish. Also pin `tauri-action` to a SHA (it holds the signing key).

## Refactor plan

**R1 — one path predicate, one manifest writer (core).** Collapse `is_forbidden_rel_path` / `is_file_safe_rel_path` / `is_forbidden_wizard_path` / `classify_zip_entry` into one exported allowlist predicate. Route the five hand-rolled manifest writers through `save_manifest` (three currently skip `touch_profile`). Give `save_manifest` a `running_names` parameter like its siblings. Also reject `C:` segments, `:` (NTFS ADS) and reserved device names in `normalize_rel_path`.

**R2 — `net.rs` (Tauri crate).** Five fetch modules re-implement one HTTP/cache/verify layer; three funnel through `comfig_fetch::download_bytes`. One `download_pinned(url, cache, Verify::{Sha256|Size|Magic}, max_bytes)` with a single timeout policy fixes the missing timeouts and size caps by construction and makes the mods.zip cache hash-verified.

**R3 — Split `commands.rs` (963 lines) by core module** (finder/library/absorb/first_run/files/comfig/launch/hud/crosshair/viewmodel/preloader/shared) with one `with_root(|root| …)` spawn_blocking helper, which makes the main-thread fix mechanical. Move `install_hud_from_catalog` and `apply_preloader_mods` orchestration into core so they're testable. Return `{code, message}` errors.

**R4 — Split `preloader.rs` (1963 lines)** into gameinfo / state / catalog / pack / apply. Read the three official VPK trees once per apply instead of twice; name snapshots by `sha256(rel)` (current `__` mangling isn't injective).

**R5 — `bridge.ts`:** replace 52 hand-written wrappers with one `call<T>(cmd, args)`; ~350 lines removed, the five unwrapped functions become impossible, and one place for structured errors. Add a `previewBridge` adapter selected once at the root so the 38 `!tauri` branches in `SettingsHost.tsx` and ~200 lines of fixture code leave production.

**R6 — Decompose `App.tsx` (1563 lines) to ~200:** `useTf2Install`, `useWriteLock` (fixes P0 #4 in one place), `useProfileLibrary`, `useFirstRun`, `useAppUpdate`; components `UpdateBanner`, `WriteLockBanner`, `AppFooter`, `FinderPanel`, `SwitchProgressList` (own file — its test currently imports the whole shell), `ReadyPanel/{ReadyHeader,ProfileMenu,PackPrompt,InheritBindsToggle}`. `AppStatusContext` for `{error, busy, running}` replaces 4-level prop drilling and the five duplicated `!running && !busy` helpers.

**R7 — Shared pane primitives:** `PaneSection`, `Switch` (3 implementations today), `ApplyBar` (4 copies), `Alert` (3), `Modal` with real focus trap (3 copies + lightbox), `ClassTabs` (2), `useSeededDraft` (4 hand-rolled copies — fixing "reseed discards unsaved edits" once covers every pane), `useCopyFeedback` (2). Move `hexToRgb`/`rgbToHex` out of `hud-ui.ts` into `lib/color.ts`.

**R8 — Split `CrosshairPane.tsx` (1105 lines)** into `CrosshairPreview` (with the scale-any-size fix), `CrosshairLibraryChips`, `WeaponOverrideTable`, `CommunityPicker`, `CrosshairDesigner`, plus `useCrosshairDraft`.

**R9 — cfglint:** `LintOptions.trust: "self" | "provided"` demoting `connect-redirect` / `disruptive-bind` / `exec-external` to warn for the user's own files; scan `exec` inside payloads; shared expansion budget; per-file save gate; lazy `summary`; drop `restart`; namespace `modules.cfg` skip to the mastercomfig location; dedupe key includes command name.

**R10 — Cargo workspace.** `[workspace] members = [".", "core"]`; delete `core/Cargo.lock` (app currently resolves zip 2.4.2 *and* 4.6.1; core only 2.4.2, so tests validate a different graph than the binary). Relax or document `uuid = "~1.11"`.
