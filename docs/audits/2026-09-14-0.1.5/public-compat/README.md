# Previous-public export compatibility: 0.1.4 to 0.1.5

Result: **PASS** on Windows, 2026-09-14. The real public 0.1.4 core wrote the source ZIP. The integrated 0.1.5 core imported it into both an empty library and a library with an active profile, re-exported it, and imported the re-export. No product source was edited for this check.

## Fixture and assertions

The public core's `profile::create_populated_profile_to` creates the synthetic source library; its `export_profile_to` writes `public-0.1.4.zip`. The source ZIP is not handwritten. Payloads are generated by the helper, including three valid VPKs generated by the public core's VPK writer.

The schema-1 fixture has 11 files: four cfg files (including a nested cfg), two HUD files, separate `compat-pack` and `-compat-pack` folders, separate `compat-vpk.vpk` and `-compat-vpk.vpk` archives, and a shared `mastercomfig-base.vpk` blob. The paired packs contain different bytes. Four local mod records, a local HUD record with two options, two distinct ignored-pack names, and safe launch options exercise portable metadata.

Assertions passed:

- Every payload path, SHA-256, storage class, and file byte survives all three 0.1.5 imports. Both independent folder/VPK pairs remain separate.
- HUD options, all four mod records and their verified counts, ignored packs, and launch options match the public export exactly. Safe folders acquire no unsafe-folder marker.
- Empty-library imports keep the active profile unset. Import into an existing library keeps its active ID and every existing active-profile byte unchanged. Imported profiles receive new identities and correctly mark launch settings as awaiting projection.
- Public and new exports leave their source libraries unchanged. Both synthetic install trees retain every directory and file byte.
- The new re-export contains the same metadata and payload entries. An explicit whole-file byte comparison also passes: both ZIPs have SHA-256 `f6f6b71cdb9a106c72730701c40bd8fa986afcac4a1b757c2c9cb633b21da62e`.
- The new core imports that re-export successfully without activating it.

All roots, libraries, staging files, and ZIP outputs are under this helper's fresh run directory. Only explicit-path core APIs are called. Installed profiles, actual game files, and global app-data entry points are not used. The core's normal read-only process checks remain in place.

## Reproduce

Create detached checkouts at the exact commits above, with this sibling layout (the common parent may be anywhere):

```text
<projects>/execs-014-compat/
<projects>/execs-015/
<projects>/execs-015-evidence/compat-public/Cargo.toml
<projects>/execs-015-evidence/compat-public/Cargo.lock
<projects>/execs-015-evidence/compat-public/src/main.rs
<projects>/execs-015-evidence/compat-public/run.ps1
```

From `compat-public`, run `./run.ps1` with a fresh simple run name. Each run refuses an existing output directory and preserves earlier evidence. Cached locked dependencies are required by `--offline`; on a fresh machine first run `cargo fetch --locked --manifest-path Cargo.toml`. A different later product commit is accepted only when its core tree remains the exact tested tree.
