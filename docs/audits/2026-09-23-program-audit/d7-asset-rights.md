# D7 — third-party asset rights register

**Owner containment decision, September 25, 2026.** The owner accepted the current containment as D7's resolution. No new download, build or selection path uses CompVMInstaller, Venom, TF2Hitsounds, comfig.app hosted sounds or cueki's bundle. This records a product decision, not a legal opinion or a grant from any author.

## Implementation choices if grants remain unavailable

- The Venom, TF2Hitsounds and comfig hosted-sound catalogs are retired for new downloads. Native commands refuse the old remote picks, including cached sources. Previously saved VTFs and WAVs remain readable, playable, switchable and exportable from profile-owned bytes; missing local bytes fail without replacing the current pack. A baked boost on a saved remote WAV cannot be changed without a new source. The UI explains these limits and offers first-party, installed-game or user-import choices. This closes the new-download path, not rights for existing exports.
- A saved Casual setup selection of the remaining cueki addons or library particles requires a cached, hash-verified `mods.zip` during profile-switch preflight; Flat, Developer and the two overlay choices use their pinned author archives. New bundle downloads and selections are retired. If an inactive target profile lacks that cache, the app offers a revision-bound review to remove only its saved cueki choices, preserve direct-author and profile-owned sources, and retry; Cancel leaves the profile unchanged. Active restore and interrupted-switch recovery retain their existing guards. This compatibility path does not establish rights for the cached collection or for sharing other installed custom packs.
- Viewmodels now imports, replaces and removes a user-supplied compatible VPK; old profile-owned packs remain switchable and exportable. This deliberately removes the earlier one-click, 64-group builder. Restoring an equivalent builder without the CompVMInstaller ZIP would require independently licensed QC/SMD source data and group mapping, or a verified pipeline derived from the player's own installed assets. Neither substitute has been implemented or validated. The Viewmodels pane no longer shows CompVMInstaller JPEGs, and the Crosshair scene now uses a labeled neutral code-native reference. Neither is an in-game render of a selected pack.
- The [read-only stock-MDL probe](d7-stock-mdl-probe.md) parses nine installed class models and their sequence references, and the [independent mapping study](d7-stock-mapping-study.md) specifies the item-to-activity derivation and retail validation still needed. The [legacy-to-stock compatibility check](d7-viewmodel-local-rebuild-bridge.md) found exact local sequence/animation targets for all 405 legacy stems and six Soldier forced stems on one verified TF2 patch; it is a name-level bridge, not independently derived group semantics or rendered parity. An [audit-only Scout root experiment](d7-scout-root-offset-probe.md) changed one root-position field in a hash-pinned scratch model. A separate [weapon-bone experiment](d7-scout-weapon-bone-probe.md) changed only bounded weapon-position fields in an exact stock Scout animation copy, but found zero-weight sequence cells that limit a hands-visible claim. Neither experiment has a rendered or retail TF2 result or proves a 64-group replacement. The [Valve asset/export review](d7-valve-export-rights.md) records the official TF2 redistribution boundary and the current profile ZIP path. A player-install pipeline must resolve export of transformed Valve model bytes before being called rights-cleared.
- A grant must identify the rights holder, the covered files/revision, allowed display/download/transform/install uses, redistribution terms if any, and any attribution or share-alike obligations. For collected works, check underlying contributors and source-game rights separately. Record the evidence in `THIRD_PARTY.md` and package notices, then test the chosen implementation and existing-profile behavior before checking D7.

The [September 4 owner continuation decision](../../release-0.1.1.md) kept the then-existing integrations for 0.1.1. It explicitly did not claim an author license grant and does not close this audit finding.
