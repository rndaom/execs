# Launch and lock plan (issues 4-6)

Audit: the process matcher omits `tf.exe`; pending launch survives indefinitely and Cancel refuses while Steam runs; a closed Steam mismatch silently takes `write-then-launch`. Launch autosave also writes Steam automatically. Existing process polling, durable operation token/marker, Modal, buttons and launch comparison surfaces can support the corrections without new styling.

1. Recognize exact `tf.exe` (case-insensitive basename) on Windows and Proton alongside existing binaries; reject near matches and retain server exclusions.
2. Cancel launch wait checks TF2 twice under the durable completion guard, permits Steam to remain running and never stops a process. One-click header release explains in its tooltip that queued launches must be cancelled in Steam first. Bound passive waiting to ten minutes, then release only after repeated absent TF2 observations; restored waits preserve the original handoff marker modification time, with a monotonic remaining deadline; unreadable legacy timestamps receive one bounded recovery wait. Timeout is surfaced through lifecycle status and a persistent app notice. Normal process lock remains authoritative if TF2 starts later. Preserve token identity and marker error refusal. Header copy describes releasing the wait, not stopping TF2.
3. Every mismatched launch offers the same review whether Steam is open or closed: keep Steam options and launch, adopt Steam options into the active profile and launch, replace with reviewed profile options (restart only if open), or cancel. Bind mutation to native current profile/root/account and exact raw Steam options via a review token, recheck after Steam closes and at write. Drift requires another review. Display raw Steam options so forbidden tokens cannot be hidden by sanitization; adopting refuses forbidden options rather than silently transforming them.
4. Autosave, profile switches/retries and viewmodel/preloader changes save profile options only. Explicit Write to Steam uses the same reviewed native operation; no background autosave overwrites externally edited Steam options. Reuse launch status text and existing controls; clipboard does not mark synced.

Tests: exact process names on both platforms; cancellation with Steam open, running TF2 and delayed TF2 start; token/marker mismatch; bounded monitor and restored wait; mismatch review open/closed; unchanged/in-sync launch; reviewed profile/account/options drift including Steam exit flushing newer options; raw forbidden options; adoption preserves Steam bytes; existing launch pane and pending-settings regressions. Use disposable filesystem/process fixtures only, no real Steam/game launches or player writes. Run focused Rust and UI tests, formatter/types, then parent coordinates workspace checks.

Documentation: inspected project source and local AGENTS. sysinfo official API documents process-name access (https://docs.rs/sysinfo/latest/sysinfo/struct.Process.html#method.name); Steam Support launch-options page is https://help.steampowered.com/en/faqs/view/7D01-D2DD-D75E-2955 (tool returned minimal page content); Valve developer protocol page https://developer.valvesoftware.com/wiki/Steam_browser_protocol returned 403. No remote source promises a cancellable URI launch acknowledgment, so completion is based on observed processes and explicit bounded wait semantics, not an inferred Steam cancellation API.
