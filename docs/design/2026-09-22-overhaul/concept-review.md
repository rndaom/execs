# Visual concept review

22 September 2026. The independent reviewer inspected the five Foundry boards, the initial Signal and Afterhours core boards, and audit captures 021, 031, 057 and 063. The primary agent subsequently inspected all fifteen generated boards; supplemental observations follow below. This is a review of rendered images, not a test of an implemented redesign.

The options are sufficiently distinct for choosing a visual direction. Their strongest differences are palette and surface treatment; they share the same sidebar/header structure and broadly similar desktop density. They should be presented as three coherent treatments of execs, not three radically different information architectures. No wholesale regeneration is necessary for that decision.

## Foundry consistency and fidelity

Foundry carries a recognizable warm palette, header, sidebar, type hierarchy and orange emphasis across all five boards. Task-specific arrangements are a strength: Binds uses mappings, HUD uses media cards, Sounds pairs two slots, and Files uses a workbench. A shared shell does not force one content template onto every pane.

## Implementation invariants

The [repository contract](G:/Projects/execs/AGENTS.md), actual component behavior and verified release scope take precedence over generated text. Before implementation, reconcile every panel against the [surface inventory](G:/Projects/execs/docs/design/2026-09-22-overhaul/research/surface-inventory.md), including features omitted by the boards.

- **Keep real actions and save ownership.** Binds and small settings retain autosave; do not add a generic Apply changes step. Crosshair color/display size autosave, while custom assets and mounted-file mode changes retain explicit actions. Keep **Save to library** distinct from **Build pack**. Viewmodels keeps its supported build/import workflow, Mods keeps **Apply mods**, and HUD install/update/import remain explicit. [Binds source](G:/Projects/execs/apps/desktop/src/BindsPane.tsx:68), [Crosshair action](G:/Projects/execs/apps/desktop/src/CrosshairPane.tsx:358), [Designer action](G:/Projects/execs/apps/desktop/src/crosshair/CrosshairDesigner.tsx:251).
- **Keep Files explicit and stateful.** Preserve visible Save, conditional Discard, dirty markers, document drafts/history and Save/Discard/Cancel transition guards. Problems come from cfglint with real file, location, severity and save policy; never copy invented warnings. [Exit guard](G:/Projects/execs/apps/desktop/src/hooks/useFilesExitGuard.tsx:201), [real tracer command](G:/Projects/execs/apps/desktop/src/GameplayPane.tsx:159).
- **Keep game/Steam locks truthful.** Editing can continue while TF2 runs, with drafts retained until permitted to save; heavy writes keep their guard and reason. Launch remains profile-owned and writes Steam configuration only while Steam is closed, with Copy guidance otherwise. A screenshot of explanatory copy does not certify a native guard. Progress and completion must come from actual operations.
- **Use real metadata and assets.** No fake GameBanana download/rating numbers, authors or availability claims. HUD rankings retain source coverage/missing-data disclosures. Reuse authorized, credited sources or the user's decoded assets for shipped previews; no generated game/HUD/item art becomes a product preview asset. Concept FOV images cannot imply calibrated output.
- **Preserve scope and identity.** Inventory remains account-owned, read-only and development-only unless separately assigned. Proposed settings/deletion surfaces stay labeled as proposals. Current labels, preset/addon lists, numeric ranges, per-weapon choices, all nine classes and source attribution survive any visual simplification. Consistent navigation highlights must match the visible pane.
- **Validate the chosen direction in code.** Normalize shell groups, icon sizes, spacing and controls; preserve accessible semantics and keyboard behavior. Check contrast at actual token colors and small-window layout rather than inferring compliance from a board. The [motion proposal](G:/Projects/execs/docs/design/2026-09-22-overhaul/research/motion-spec.md) still needs implementation and reduced-motion/performance testing; static PNGs prove no transitions.

## Revision recommendation

Keep these boards for the initial choice with visible concept-only notes. Targeted correction is necessary before any board becomes an interaction specification: autosave versus explicit build/save, fabricated metrics/lint, navigation highlights, supported control names and source imagery. That reconciliation can happen in the selected direction's source-backed mockup; generating every board again is not necessary solely to fix illustrative text. A further image revision is justified if those false promises remain prominent without adjacent qualification, or if the user wants more divergent layouts after comparing the three treatments.

## Supplemental review of the completed suites

All three suites contain five boards with twenty visible page/state views. The delivered PNGs are 1672 × 941 pixels, despite the prompts requesting a larger canvas. They support layout and art-direction selection; small generated text is not suitable as a final production specification. No image has been upscaled or rewritten to imply additional detail.

Signal's later boards retain crisp blue surfaces and aligned tools; Afterhours retains olive surfaces, brass accents and softer groups. Both carry the same tasks through different compositions. The remaining anomalies reinforce the invariants above:

- Both installed-HUD concepts can highlight Crosshair instead of HUD; some state boards duplicate or mislabel navigation entries. Normalize the shell from the source inventory.
- Some buttons revert to the source app's orange despite the intended palette. The selected system needs a single defined primary-action token plus separate semantic warning/destructive tokens.
- Signal's Launch string contains extra generated flags absent from its visible tokens. Afterhours' Files panel invents a lint finding; neither is an instruction to change cfg policy or recommend flags.
- Afterhours' import review says a command will be added to autoexec. That statement is false for the proposed import behavior: trusted imported cfg bytes remain unchanged, and import does not activate the new profile.
- Invented mod counts, authors, item art/attributes, addon names and transparency modes remain illustrative. Only verified real data and authorized imagery may enter the application.
- First-run mockups sometimes retain active-profile or launch chrome. The implementation must follow confirmed-install and first-run state, with no early game-file writes or misleading active profile.

The gallery places concept labels beside every board and catalog-data qualifications beside each Workspaces board. The durable implementation contract remains the repository guide, source-backed audit and selected release scope. These notes make the visual options reviewable without treating generated labels as approved behavior.
