# Windows previous-public capability: run 35937290574

This [hosted run](https://github.com/rndaom/execs/actions/runs/35937290574) **failed** on draft PR #60 head `65d20bd905435a6d4813b39c13537339d94b7b2b` through the tested PR merge `4c363147a62a624a7bda7f2ecae13541d505d37f`. It is a development probe of the actual public v0.1.8 NSIS installer, not a candidate Windows installer or signed updater result.

The harness verified the public installer signature and exact asset hash, installed it with exit code 0 into its owned disposable root, and observed `execs.exe` plus a production WebView2 child. The WebView2 command line carried the isolated user-data directory and loopback-debug policy. The first [inspection receipt](evidence/04-inspect-receipt.json) had no listening debug socket; subsequent inspections refused a changed process identity. The host also could not load its UI Automation assembly. The run stopped before any native export, candidate upgrade, import, or reopen. Its [result](evidence/result.json) reports a failed listener wait and owned-process cleanup failure, so no Windows UI qualification is claimed.

The registry policy restoration reported success and the final synthetic fixture comparison reported its original bytes preserved. The cleanup identity refusal remains a failure and requires diagnosis on a disposable hosted runner. The earlier registry-`DisplayName` strict-mode error was fixed before this run; it is a separate, resolved harness defect.

Follow-up inspection found that the harness compared the process creation timestamp string from `Process-Record` with a `DateTime` created by `ConvertFrom-Json`. PowerShell treats those as unequal even for the same UTC instant, so later inspection and cleanup falsely reported a changed identity. The empty listener list belongs only to the first, early receipt; this run cannot establish whether the listener appeared later. A focused UTC-tick comparison regression now covers the mismatch, but a fresh hosted capability run is required before claiming Windows UI behavior.
