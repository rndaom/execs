The [hosted run](https://github.com/rndaom/execs/actions/runs/35948836291) **failed** on PR head `7e3ff449124fac2444f4a012112164bdc7cf4c23` through tested merge `78c57c714b6a2f611164cbb6289d78aec9b6df18`. The harness passed 27/27 hosted preflight contracts, verified and installed the public NSIS asset, and attached to the production WebView2 UI using loopback-only listeners. The [Export trace](evidence/result.json) shows trusted pointerdown and click events on the intended Export control at `(487, 160)`. Windows PowerShell 5.1 then loaded UI Automation and found the native Save dialog. The retained [observation](evidence/native-save-observations.json) records one visible `Export profile` / `#32770` window at handle `66172` in the exact app PID `5668`, alongside a visible `execs` / `Tauri Window` main window in the same PID. The dialog contains an enabled `File name:` edit (`1001`) and `Save` button (`1`). Its Win32 `GW_OWNER` is **zero**. The harness required a nonzero owner and stopped at that check, before setting a filename or invoking Save.

This is a harness ownership mismatch. [Microsoft's `GetWindow` documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow) says `GW_OWNER` returns null when there is no owner window, and [`IModalWindow::Show` permits a null owner](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-imodalwindow-show). The artifact proves this dialog belonged to the exact app process; it does not prove that the product exported a ZIP.

The follow-up harness accepts this specific process-owned top-level route only when the export dialog is the sole visible native dialog in that process, the one visible `execs` main window is present, both UI Automation and native Win32 PIDs match the pinned app process, and the dialog is foreground. An explicit main-window owner remains a separate accepted route. A different owner, an unrelated or competing same-PID dialog, a foreign process, or changed foreground is refused. The route is recorded in the Save observation and success receipt. Process identity, exact output path, and destination absence are checked again immediately before invoking Save. Local fixtures exercise these cases in both PowerShell editions; all **28/28** focused Windows contracts, `pnpm check`, and `git diff --check` pass. A new hosted run is needed to verify actual filename entry, ZIP bytes, and normal close.

The failed probe produced no export ZIP and no normal-close receipt. It force-cleaned nine tracked child processes after failure, restored all four policy entries, and reported the original synthetic fixture bytes preserved. Neither forced cleanup nor the visible Save dialog counts as package qualification.
