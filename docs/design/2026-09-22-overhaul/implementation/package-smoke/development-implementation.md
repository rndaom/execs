# Linux development package harness

2026-09-22. The Linux part of the [accepted development proposal](development-run-plan.md) is implemented and independently reviewed. Its [first hosted workflow](run-35775130896/README.md) passed all 48 harness tests, then failed the existing packaged-credits preflight before any package was built or launched. The notices generator now adds the missing design-inspiration credit and four dependency license blocks; `--check` verifies all 470 packages locally. The original 466 blocks are unchanged. A fresh hosted package execution is still required. No installer or desktop app was run locally. Windows NSIS remains unimplemented in this new workflow. RND-251 remains open.

## Implemented scope

[development-package-smoke.yml](../../../../../.github/workflows/development-package-smoke.yml) has one Ubuntu 22.04 job, same-repository PR filtering, optional manual dispatch, `contents: read`, no persisted checkout token, a separate concurrency group and seven-day fixture-evidence retention. It builds the ordinary optimized production frontend/native executable and AppImage/Debian bundles with only a temporary `createUpdaterArtifacts: false` override. It never calls the release workflow, creates a tag, changes versions, uploads package downloads, publishes a feed or receives signing secrets. Existing release/package validators are unchanged.

The new entrypoints are:

- [development-package-guard.mjs](../../../../../scripts/development-package-guard.mjs): hosted Linux/repository/tag/signing-secret refusal, temporary version-history rehearsal, exact public release/asset selection and existing Minisign verification before old package execution.
- [development-package-fixture.mjs](../../../../../scripts/development-package-fixture.mjs): private HOME/XDG/TMPDIR, exact source-backed profile payloads, bounded ZIP inspection and phase-specific preservation assertions.
- [development-package-native.mjs](../../../../../scripts/development-package-native.mjs): external Tauri/WebKit driver, real native UI/keyboard, PID-owned GTK dialogs, exact packaged executable identity, stable captures and owned close requests.
- [development-package-smoke.mjs](../../../../../scripts/development-package-smoke.mjs): sequential AppImage manual replacement, Debian upgrade and Debian first-install cases, with independent fixture state and final comparison on success or failure.

The read-only old-package lookup must resolve the latest public release to the version derived from repository history and the actual exporter fixture, currently `v0.1.8`. Its AppImage and Debian assets must be published, non-prerelease assets with matching tag URLs, bounded sizes and valid signatures under the existing public updater key. Development candidates are unsigned; old-package signature verification does not qualify candidate updater trust.

## Native sequence and exact changes

Each upgrade case opens the installed public app, checks its native origin and two-profile library, opens `tf/cfg/config.cfg` in Files, and obtains exact text through trusted native Ctrl+A/C and the isolated X clipboard. It exports through the old app's actual Export action and PID-owned GTK Save dialog. The requested destination must exist and its original ZIP bytes must pass independent metadata/member/payload inspection. A default-location Save or an unsupported driver/dialog action fails; the harness never relocates or rewrites native output to make it pass.

After normal close is observed, AppImage testing replaces the complete portable image at the same private path; Debian testing uses the package manager to install the candidate over the public package. The candidate must render the original profiles and cfg, import the exact old UI export through its Open/review/confirm flow, and add exactly one new UUID without activating it. An explicit UI switch then changes the active ID. The visible completion detail must report that no Steam account config was found. A close/reopen must retain that selected profile and all expected bytes. Debian first install has its own fresh fixture and native read/close/reopen sequence, without claiming an old-UI export/import pass for that separate case.

The two original profiles cover cfgs, launch options, ordinary mod data, an inactive HUD and shared VPK storage. Their manifests/payloads originate in the tagged exporter; the index, IDs, names, settings and synthetic install are authored. There are 21 original protected files across the app-data and live trees. The first/no-HUD profile's four payloads form the bounded old-UI round trip. Import allows only its new manifest, three exclusive copies and one index entry; the shared blob remains exact. Switch allows only the active index UUID to change. The imported pending launch-sync flag stays true. All original profile metadata, shared/exclusive payloads, settings and synthetic live bytes remain exact. Only an empty ordinary blob `.incoming` container is allowed after import. No HUD ownership change, Steam account, game launch or Cloud write belongs to this run.

Every native child gets private HOME/XDG/TMPDIR and an environment allowlist. The parent and fixture checks refuse existing execs/Steam/TF2 processes and Steam-discovery candidates. Settings disable candidate startup update checks; the old public app may ignore that newer preference. This is not a claim of network isolation. Package-manager writes are confined to a fresh hosted VM; the script refuses local/self-hosted execution and preexisting product installations.

## Identity, failure and evidence boundaries

The actual native process is bound to the external driver's owned process group, PID, start time and executable path. Debian runtime bytes must match the inspected package and build-tree executable. AppImage runtime must use a read-only FUSE mount directly under its private temporary directory and match the inspected package ELF exactly. Extracting an AppImage is used only to inspect contents; extraction cannot satisfy its native launch row.

The AppImage's ELF need not equal the build-tree ELF: pinned Tauri CLI 2.11.4 copies the Debian tree and invokes linuxdeploy, which can strip and set RPATH on the packaged copy. The harness records both hashes and checks the exact packaged/running identity. Debian's bundler directly copies the executable. [Tauri AppImage bundler](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.4/crates/tauri-bundler/src/bundle/linux/appimage/linuxdeploy.rs), [linuxdeploy ELF operations](https://github.com/linuxdeploy/linuxdeploy/blob/master/src/core/appdir.cpp), [Tauri Debian data creation](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.4/crates/tauri-bundler/src/bundle/linux/debian.rs).

Selectors are checked against immutable `v0.1.8` source: `settings-tab-files`, `settings-files`, the profile summary and row names, Export's accessible name, Files item's full path and CodeMirror's content label. GTK dialog titles also come from that tag's native commands. New import/review/switch selectors come from current source. This establishes source compatibility; it does not substitute for the pending actual installed UI run. [Old SettingsLayout](https://github.com/rndaom/execs/blob/v0.1.8/apps/desktop/src/SettingsLayout.tsx), [old profile menu](https://github.com/rndaom/execs/blob/v0.1.8/apps/desktop/src/components/ReadyPanel/ProfileMenu.tsx), [old Files pane](https://github.com/rndaom/execs/blob/v0.1.8/apps/desktop/src/FilesPane.tsx), [old editor](https://github.com/rndaom/execs/blob/v0.1.8/apps/desktop/src/components/FilesEditor.tsx), [old dialog commands](https://github.com/rndaom/execs/blob/v0.1.8/apps/desktop/src-tauri/src/commands/library.rs).

Close evidence means an owned `WM_DELETE_WINDOW` request followed by native process disappearance before driver cleanup. The external driver owns the app child, so its exit code remains explicitly unknown. Cleanup stops only the created driver group. The final fixture comparison runs even when native work or cleanup fails; the original error and all cleanup/comparison failures remain in the receipt. A capability failure cannot become a usability pass because the process survived. Stable screenshots, native state, driver stderr, clipboard diagnostics, exact export, identity receipts and each preservation checkpoint are retained; installers are not uploaded.

## Local validation and remaining work

Local Windows validation passed **48 tests, 0 failures, 0 skips**: 13 new guard/runtime-boundary tests, 11 new development fixture tests and 24 existing package fixture/release tests. [Complete test log](development-tests-windows.txt). Scoped Biome, Node syntax/import checks, workflow YAML parsing and whitespace checks passed. [Static check log](development-static-checks.txt). This is harness validation; it is not a Linux package execution result.

The new behavioral guard suite covers local-host refusal, public metadata/signature tampering, wrong/ambiguous candidates, PID/dialog ambiguity, FUSE identity, and failures during native work, cleanup, comparison and evidence writing. The fixture suite separately tests payload/metadata corruption, wrong active IDs, extra profiles/files, staged residue, links, Steam discovery and immutable old-export compatibility. Local tests use only temporary authored files and bounded ZIP reads; no native launch or installer result is inferred from them.

Independent review corrected the portable ZIP member contract to `execs-profile.json`, keeping on-disk `manifest.json` unchanged. The regression reads the unchanged [actual tagged exporter ZIP](../profile-management/compatibility-v018/no-hud/exported-by-v0.1.8.zip), SHA-256 `3299cf62cb18da34785c309803ed2d8abad427eab9b95918ea72b1bf9259ac38`, through the real bounded inspector. Only the expected authored profile name differs in that test; the archive bytes are never rewritten. This retained archive is a test-only dependency, not a runtime fixture dependency of the hosted package script.

The first hosted run is still required to establish normal FUSE execution, WebKit driver support in both installed versions, GTK Save/Open completion, package-manager transitions and the full native round trip. A failure must retain its exact evidence and be reviewed before any assertion changes. Windows NSIS, production-key candidate signatures, real updater installation/failed-download handling, Authenticode, Steam Cloud/retail engine behavior, media decoding, Wayland and broader distribution coverage remain outside this implementation. No issue is marked Done and no release is authorized.
