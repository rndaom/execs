# execs — agent notes

Working agreement: durable product/design decisions get recorded here as they are made.

## Product identity
- Name "execs" is a working name — renameable before launch.
- The product is a **Windows + Linux desktop companion** (Tauri 2 + existing React/TS UI, `cfglint` as a library). Not a website.
- The Cloudflare community hub (Steam login, browse, upload, R2, D1) is **parked**. Do not build hub features in parallel.
- V1 audience: TF2 players setting up a fresh install or switching named setups. No Steam login required.
- Everything we ship is **first-party** except mastercomfig (integrated, not rebuilt). Do not embed other community apps.

## Integrity line
- Default surface is file-safe: write `tf/custom/`, `tf/cfg/overrides/` (or vanilla `tf/cfg` user files if comfig is absent), and TF2's Steam Cloud `config.cfg` copy.
- **Preloader exception (user decision, 2026-08-31):** the earlier blanket ban on `gameinfo.txt` edits and official-VPK patching is revoked *for the preloader feature only*. The user researched it and wants the full cueki-style preloader shipped, including its default mod library. Allowed, under hard conditions:
  - `gameinfo.txt`: only the reversible comment toggle on the `type multiplayer_only` line (`type` ↔ `//type`), byte-preserving everything else, pristine copy backed up to app data before the first edit.
  - Official VPKs: only **in-place, size-preserving** patches of `particles/*.pcf` DATA in the sibling archives (pad shrunk files with spaces, refuse larger). **The `_dir.vpk` file is never written — not even the entry CRC.** Hard-learned (2026-08-31 field incident): the directory carries Valve's tree checksum + signature and sv_pure validates against the directory's stock CRCs; rewriting a CRC breaks the tree checksum and the engine rejects the ENTIRE tf2_misc archive on pure servers (every model ERRORs, every material goes magenta). The stale stock CRC over modded data IS the bypass — cueki's data-only patching is deliberate, not sloppy. Tests assert the `_dir.vpk` stays byte-identical through patch and revert. Every entry is **snapshot-first** into app data; "Restore stock files" reverts everything; a RESIZED VPK (TF2 update) invalidates snapshots — mtime drift alone never does.
  - Still absolute: never write `tf/steam.inf`, never `tf/cfg/user/`, never any of this while the game runs, never store `+quit`/`-autoconfig`-style launch damage.
- The preloader lives in `core/src/preloader.rs` + `core/src/pcf.rs` (clean-room PCF/DMX engine — parse, shrink passes, rebuild; cross-validated byte-for-byte against cueki's pipeline on the full default library, with cueki's python-hash-collision merges deliberately not reproduced). Default mods come from cueki's pinned `mods.zip` release (v1.7.1, sha256-verified, cached). Behavior parity kept: blood_trail→npc_fx rename, `_dx80` twins, disguise.pcf material-swap-only rule, duplicate-carrier rebuilds (item_fx/halloween/bigboom/dirty_explode; keep-lists derived at runtime from the user's own vanilla files, so TF2 updates can't strand us on a stale map), `$ignorez` scrub of packed VMTs. Addon content packs into a single global `tf/custom/execs-preloader.vpk` (not profile-owned; profile switches leave it alone; revert removes it). **Enforced** by `GLOBAL_CUSTOM_FILES` in `core/src/surface.rs`, which keeps it out of the live profile surface entirely: otherwise absorb prompts to adopt it after every install, and adopting it means the next profile switch deletes the pack while the global particle patches stay — particles then point at materials that no longer exist (magenta effects). A drift-guard test asserts the exclusion names the same file the writer does.
- First-party Casual preload (RND-164) is a listen-map precache, now cueki-parity: `sv_pure -1; sv_allow_point_servercommand always; map itemtest; wait 10; disconnect; wait 1; clear; playmenumusic`. Vanilla profiles use `+exec execs_preload`; mastercomfig profiles use `+exec overrides/execs_preload`. The cfg is shared by viewmodel packs and the mods preloader: installing mods ensures it for the active profile; full revert removes it unless a viewmodel pack still uses it. Remade in-house — do not vendor cueki/Pilso/Horsie code (GPL): behavior only, clean-room Rust.
- Building viewmodel packs runs TF2's own `bin/studiomdl.exe` with `-game` pointed at an **isolated staging root** (minimal gameinfo.txt under app data) — never the live `tf/` tree. Verified working against a real install; output `.mdl` is read from staging and packed with our own VPK writer (Valve's `vpk.exe` is not used).
- Skins/models/particles in `tf/custom/` may be stored and switched. On Valve Casual they survive only with the preload (and the gameinfo bypass for materials/models). Community/listen servers need neither. Do not claim otherwise.
- Never write `tf/cfg/user/` (removed in mastercomfig 9.9.3). Never write `tf/steam.inf`.

## Profiles
- A profile is the **entire file-safe customization surface**: user cfg layer, `tf/cfg/config.cfg`, **all of `tf/custom/`**, and a launch-options string.
- Switching is **exact replace**, not merge. Inactive profiles live in app data, never under `tf/custom/` (TF2 would mount them).
- Library: Windows `%AppData%\execs\profiles`, Linux `~/.local/share/execs/profiles`. Live game folder holds only the **active** set.
- Export/import is a zip. `mastercomfig-base.vpk` may be shared **by hash** across profiles; everything else is exclusive.
- App can stay open while TF2 runs. **No writes** while `tf_win64.exe` / `tf_linux64` is running.
- After TF2 quits: owned-file / `config.cfg` drift **absorbs automatically** into the active profile. New or deleted packs in `tf/custom/` **prompt, default Update**. Never silently roll back to an old snapshot.
- Steam Cloud stays on. On absorb and on switch, write the same `config.cfg` bytes to `tf/cfg/config.cfg` and `userdata/<id>/440/remote/cfg/config.cfg`. Do not delete Cloud files (Steam redownloads them).
- Progress UI shows real steps (game closed → pack current → remove live packs → write files → Cloud → done), never invented ones. The presenter paces genuinely-reported steps at a minimum display duration (`SWITCH_STEP_MIN_MS`) and fills a step-driven bar so a milliseconds-fast switch still reads as a sequence; no percentages, no steps marked done before their event.

## First run and new profiles
- Find TF2 by scanning Steam libraries (registry, `libraryfolders.vdf`, `~/.local/share/Steam`, `~/.steam/steam`, Flatpak data dir). Confirm `tf/steam.inf` app `440`. Always offer Browse. Multiple installs → picker. Remember one root; profiles are tied to it. No silent write until the path is confirmed.
- **Existing customization:** first launch only **Save current as…**. Do not install comfig on top until they ask.
- **Unused install:** first launch is the setup wizard.
- **Create new profile** (after they already have one) is when the wizard runs for existing users.
- A new profile is a **fresh TF2**: stock binds from Valve `config_default.cfg`, wizard comfig layer, empty `tf/custom/` except official VPKs they picked. Different profile = different binds.
- Inherit-binds is a **settings checkbox**, off by default, not a dialog on create.
- Do not run the nuclear clean-up (`delete tf/cfg` + `-autoconfig -default +quit`) as a normal switch or create.

## mastercomfig
- Do not rebuild the VPK core, interp research, class-cfg takeover, or comfig.app's bind/weapon-VTF customizer.
- V1 in-app: **our UI** for preset, modules, addons. Fetch **official GitHub Release** VPKs at install/update time. Write `tf/cfg/overrides/` (`modules.cfg`, `setup_hook.cfg`, etc.).
- Credit + link to https://comfig.app and their support/donate. Do not brand as official mastercomfig. Do not bundle a stale VPK in our repo as "ours."
- Extras and the preset guide open **in-app**: `open_embedded_page` builds a dedicated WebviewWindow (`comfig-extras` → https://comfig.app/app/, `comfig-docs` → https://docs.comfig.app/latest/). Remote pages get no Tauri IPC — never add them to a capability. Import `comfig-custom/` if they used it.
- Every other external link goes through `openExternal` (tauri-plugin-opener) — plain `target="_blank"` anchors are silently swallowed by wry on Windows.
- Preset preview images are the real mastercomfig koth_sawmill screenshots (MIT, comfig-app repo) vendored under `src/assets/presets/`, re-encoded 1280×720. Never ship AI-generated preview art.

## V1 settings UI
- **Comfig** — preset, modules, addons. No "packages installed" status text when everything is fine; only problems (not installed / read-only / saving) get a status pill.
- **Binds** — click-to-record for usual actions (movement, jump/duck, medic, use, voice, loadout). No alias/script studio.
- **Gameplay** — FOV, viewmodels, and obvious toggles. First-party; writes overrides. Also mirrors the transparent-viewmodels **addon** as an instant-apply toggle (comfig-layer profiles with packages only; it is an addon VPK, never a cvar or module — nothing is written to `execs_gameplay.cfg` for it).
- **HUD** — hud-db catalog, pinned GitHub zip install (one HUD mounted), schema options for popular HUDs. First-party apply; do not embed TF2HUD.Editor. Catalog is paginated (`HUD_CATALOG_PAGE_SIZE`) and each entry's hud-db screenshots open in an in-app lightbox (video URLs filtered out; Imgur albums stay external links).
- **Crosshair** — default in-game crosshair controls plus the **custom crosshair** builder ("custom crosshairs", not "per-weapon crosshairs"). Sources: first-party shapes, imported PNG, the **parametric designer** (style/size/thickness/gap/dot/outline/shadow/opacity → real 64×64 RGBA, params persisted on the record as `design`), and the **community pack** (Venom Crosshairs, 173 static entries pinned to hbivnm/Venom-Crosshairs-List@2e7036cd, fetched on demand, cached, written into the pack **verbatim** with their own dimensions in the weapon scripts; the 3 animated crossanim_* entries are excluded; credit HbiVnm + community authors). Named library entries live as bytes in the pack itself (manifest stores only name→format); re-apply recovers missing bytes from the pack. The stock live preview renders Valve's REAL sprites decoded from the user's own `tf2_textures_dir.vpk` (`get_stock_crosshair_sprites`, DXT/BGRA decoder in `core/src/vtf_read.rs`), with extracted-geometry SVG as fallback; scale = ×`cl_crosshair_scale`/32; `cl_crosshair_alpha` is stored but the engine draws opaque. The builder bakes an optional RGB tint into shape/designer VTFs and apply normalizes `cl_crosshair_red/green/blue` to 255; weapon overrides offer an "All classes" per-slot mode (picking the base shape clears overrides so the fallback keeps working) and copy-class-to-all fans out to OTHER classes only. Our VTF writer uses the spec header layout (bumpScale@48, format@52, mips@56 — an older build wrote these 4 bytes early). Default controls keep writing the gameplay override; the builder writes `tf/custom/execs-crosshairs/`.
- **Viewmodels** — **Yttrium-style only** (user decision 2026-08-31): per-class checkbox groups (64 groups generated from CompVMInstaller's source into `core/src/viewmodel_groups.rs` + `lib/viewmodel-groups.ts`, with two upstream bugs fixed — Wrangler installs, dragons_fury_inspect_end included; hiding any Soldier group force-hides the Original like upstream). Build = fetch Yttrium's `animations.zip` (pinned commit b215a5cd, sha256-verified, cached), rewrite chosen SMDs off-screen (`hide_smd_sequence`, frame counts preserved), compile per class with the install's own studiomdl in staging, pack with our VPK writer, install through the import machinery (`ViewmodelSource::Compiled`, `options.hidden` CSV, `options.mode`). **Two hide modes** (`ViewmodelHideMode`, user request 2026-08-31): `full` moves every bone off-screen, so the weapon *and* the arms vanish — CompVMInstaller's behavior and the default, including for packs built before the option existed; `weapon` rewrites only the `weapon_bone*` / `vm_weapon_bone*` rows, which every class parents to `bip_hand_L`/`bip_hand_R`, so the weapon goes and the hands keep animating (all frames preserved, nodes section untouched). Either way a hidden weapon is also hidden in third person — TF2 shares one c_ model between both views; say so in the UI rather than implying first-person-only. Credit Yttrium; assets are fetched from his repo, never vendored. The Horsey-editor concepts (origin/rotate/keep-visible/static/weapon extras, QC/SMD knobs, `viewmodel_compile_capability`) are REMOVED, not hidden — do not reintroduce without a new product decision. Prebuilt VPK import and Casual preload remain. First-person reference imagery is real per-class/slot renders from the Official TF2 Wiki (Valve content, fan use, credited), vendored under `src/assets/viewmodels/`. File-safe FOV/min stay on Gameplay.
- **Files** — raw cfg + `cfglint`. Files are classified by origin (user/app vs engine/HUD/pack/comfig-import): non-user files are read-only and lint **advisory-only** (block findings demote to warns via `advisoryPaths`), so provided content can never lock the user's own saves. `tf/cfg/config.cfg` stays strict-with-exemptions and editable.
- **Launch options** — copy-to-clipboard. Auto-write `localconfig.vdf` only if Steam is already closed. Never force-quit Steam to finish setup. Never store `-autoconfig`, `-default`, `-dxlevel`, or `+quit` on a profile.

## Updates
- The app has an **in-app updater**: GitHub Releases + Tauri updater. Check on launch and via footer **Check for updates**. Show “update available,” they click **Install**. **Later** dismisses for the session. No silent force-replace, no analytics/telemetry.
- Endpoint: `https://github.com/rndaom/execs/releases/latest/download/latest.json` (published, non-prerelease tags only). Sign with GitHub secrets `TAURI_SIGNING_PRIVATE_KEY` and optional `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Pubkey lives in `apps/desktop/src-tauri/tauri.conf.json`. Never commit the private key.
- Linux updates are AppImage. `.deb` is first-install only. Windows uses NSIS (`installMode: passive`). No macOS.
- mastercomfig VPK updates are a **separate** control on the Comfig pane (their GitHub releases, not ours).

## Design decisions
- Calm dark product surface, single warm accent: bg `#121212`, warm ink `#ECE7DA`, accent = item orange `#CF6A32`, item-quality colors for badges only. The TF2 identity lives in the accent and warm ink — **no TF2-style display face** (Big Shoulders was removed by user decision 2026-08-30) and no uppercase headings; all type is Inter with a weight/size hierarchy, uppercase reserved for the tiny `.eyebrow` label.
- De-carded layout: pages are flat sections separated by hairlines (`.section`); rows use dividers, not per-row boxes. Boxes are reserved for real surfaces (`.surface`: editors, previews, media), overlays (`.overlay`: popover, progress, prompts), and selectable option tiles. Buttons are `.btn`/`.btn-primary`/`.btn-ghost` (rounded-lg); `rounded-pill` is for badges and toggle knobs only.
- Not affiliated with Valve / Steam. Credit mastercomfig where we use it. "Powered by Steam" footer is hub-era; desktop copy still needs a not-affiliated disclaimer.
- TF2 root is remembered only after Confirm. Settings live at Windows `%AppData%\execs\settings.json` and Linux `~/.local/share/execs/settings.json` (`{ "schema": 1, "tf2Root": "...", "inheritBinds"?: false }`). Do not use Tauri's `com.rndaom.execs` app-data dir — RND-147 puts `profiles/` next to this file.
- Finder: Steam roots (Windows `SteamPath` / `InstallPath`, Linux ticket paths plus `~/.steam/root` and lowercase `steam`) → `libraryfolders.vdf` / `appmanifest_440.acf` → accept only after `tf/steam.inf` app `440`. Multiple installs are a picker. Browse always stays visible. A `tf/` pick normalizes to its parent. A stored root that fails validation is unconfirmed.
- Write lock: process **name** `tf_win64.exe` (Windows) / `tf_linux64` (Linux). `refuse_if_running()` wraps live-surface and profile-library writes. Confirming the TF2 root and toggling inherit-binds are app-data settings writes and stay allowed while the game is open. Do not lock on `steam`, `srcds`, `hl2.exe`, or Proton `tf_win64.exe` on Linux.
- Crash hardening: release builds do **not** use `panic = "abort"` (one background-thread panic must not kill the app); a panic hook logs to `<execs data dir>/logs/panic.log`; the lock poller wraps each tick in `catch_unwind`; heavy commands (save/absorb, crosshair apply, HUD match) run in `spawn_blocking`, never on the main thread; the VPK reader range-reads sibling archives and supports filtered reads (`read_vpk_dir_file_filtered`) so weapon-script loading never materializes gigabytes.

## Conventions
- Plain `package.json` scripts only (Windows dev machine) — no bash-isms.
- LF line endings enforced via .gitattributes; cfg fixtures must never be CRLF.
- `design-qa.md` is a dated QA log; add an entry per visual QA pass.
- **Launching the real game for verification must not change the user's settings.** Never pass video-mode flags (`-w`, `-h`, `-windowed`, `-noborder`, `-fullscreen`, `-dxlevel`): Source persists the mode it ran with into `HKCU\Software\Valve\Source\tf\Settings` (`ScreenWidth`/`ScreenHeight`/`ScreenWindowed`/`ScreenNoBorder`), so the user's resolution stays changed afterwards — hit for real on 2026-08-31. `-condebug` (writes `tf/console.log`) is fine; `-console` is fine but persists `con_enable "1"` into config.cfg, which then absorbs into the active profile. Launch bare, read `console.log` for evidence, and back up + restore anything a test must change.
