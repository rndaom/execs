# execs — agent notes

Working agreement: durable product/design decisions get recorded here as they are made.

## Product identity
- The product is a **Windows + Linux desktop companion** (Tauri 2 + existing React/TS UI, `cfglint` as a library). Not a website.
- There is no community hub, Steam login, browse or upload. Do not build one.
- V1 audience: TF2 players setting up a fresh install or switching named setups. No Steam login required.
- Everything we ship is **first-party** except mastercomfig (integrated, not rebuilt). Do not embed other community apps.

## Integrity line
- Default surface is file-safe: write `tf/custom/`, `tf/cfg/overrides/` (or vanilla `tf/cfg` user files if comfig is absent), and TF2's Steam Cloud `config.cfg` copy.
- **Preloader exception (user decision, 2026-08-31):** the earlier blanket ban on `gameinfo.txt` edits and official-VPK patching is revoked *for the preloader feature only*. The user researched it and wants the full cueki-style preloader shipped, including its default mod library. Allowed, under hard conditions:
  - `gameinfo.txt`: only the reversible comment toggle on the `type multiplayer_only` line (`type` ↔ `//type`), byte-preserving everything else, pristine copy backed up to app data before the first edit.
  - Official VPKs: only **in-place, size-preserving** patches of `particles/*.pcf` DATA in the sibling archives (pad shrunk files with spaces, refuse larger). **The `_dir.vpk` file is never written — not even the entry CRC.** Hard-learned (2026-08-31 field incident): the directory carries Valve's tree checksum + signature and sv_pure validates against the directory's stock CRCs; rewriting a CRC breaks the tree checksum and the engine rejects the ENTIRE tf2_misc archive on pure servers (every model ERRORs, every material goes magenta). The stale stock CRC over modded data IS the bypass — cueki's data-only patching is deliberate, not sloppy. Tests assert the `_dir.vpk` stays byte-identical through patch and revert. Every entry is **snapshot-first** into app data; "Restore stock files" reverts everything; a RESIZED VPK (TF2 update) invalidates snapshots — mtime drift alone never does.
  - Still absolute: never write `tf/steam.inf`, never `tf/cfg/user/`, never any of this while the game runs, never store `+quit`/`-autoconfig`-style launch damage.
- The preloader lives in `core/src/preloader.rs` + `core/src/pcf.rs` (clean-room PCF/DMX engine — parse, shrink passes, rebuild; cross-validated byte-for-byte against cueki's pipeline on the full default library, with cueki's python-hash-collision merges deliberately not reproduced). Default mods come from cueki's pinned `mods.zip` release (v1.7.1, sha256-verified, cached). Behavior parity kept: blood_trail→npc_fx rename, `_dx80` twins, disguise.pcf material-swap-only rule, duplicate-carrier rebuilds (item_fx/halloween/bigboom/dirty_explode; keep-lists derived at runtime from the user's own vanilla files, so TF2 updates can't strand us on a stale map), `$ignorez` scrub of packed VMTs. Addon content packs into a single global `tf/custom/execs-preloader.vpk` (not profile-owned; profile switches leave it alone; revert removes it). **Enforced** by `GLOBAL_CUSTOM_FILES` in `core/src/surface.rs`, which keeps it out of the live profile surface entirely: otherwise absorb prompts to adopt it after every install, and adopting it means the next profile switch deletes the pack while the global particle patches stay — particles then point at materials that no longer exist (magenta effects). A drift-guard test asserts the exclusion names the same file the writer does.
- First-party Casual preload is a listen-map precache, now cueki-parity: `sv_pure -1; sv_allow_point_servercommand always; map itemtest; wait 10; disconnect; wait 1; clear; script_execute randommenumusic` (`playmenumusic` is not a command — the menu music is a VScript). Vanilla profiles use `+exec execs_preload`; mastercomfig profiles use `+exec overrides/execs_preload`. The cfg is shared by viewmodel packs and the mods preloader: installing mods ensures it for the active profile; full revert removes it unless a viewmodel pack still uses it. Remade in-house — do not vendor cueki/Pilso/Horsie code (GPL): behavior only, clean-room Rust.
- Building viewmodel packs runs TF2's own `bin/studiomdl.exe` with `-game` pointed at an **isolated staging root** (minimal gameinfo.txt under app data) — never the live `tf/` tree. Verified working against a real install; output `.mdl` is read from staging and packed with our own VPK writer (Valve's `vpk.exe` is not used).
- Skins/models/particles in `tf/custom/` may be stored and switched. On Valve Casual they survive only with the preload (and the gameinfo bypass for materials/models). Community/listen servers need neither. Do not claim otherwise.
- Never write `tf/cfg/user/` (removed in mastercomfig 9.9.3). Never write `tf/steam.inf`.

## Profiles
- A profile is the **entire file-safe customization surface**: user cfg layer, `tf/cfg/config.cfg`, **all of `tf/custom/`**, and a launch-options string.
- Switching is **exact replace**, not merge. Inactive profiles live in app data, never under `tf/custom/` (TF2 would mount them).
- Library: Windows `%AppData%\execs\profiles`, Linux `~/.local/share/execs/profiles`. Live game folder holds only the **active** set.
- Export/import is a zip. `mastercomfig-base.vpk` may be shared **by hash** across profiles; everything else is exclusive.
- App can stay open while TF2 runs. **No writes** while `tf_win64.exe` / `tf_linux64` is running.
- After TF2 quits: owned-file / `config.cfg` drift **absorbs automatically** into the active profile. New or deleted packs in `tf/custom/` **prompt, default Update**. Never silently roll back to an old snapshot.
- **Junk is never a pack:** any `*.execs-part` side file (what `write_atomic` leaves when it is killed between write and rename), Valve's own top-level `tf/custom/readme.txt`, and the `tf/custom/workshop/` download tree — `STOCK_CUSTOM_ENTRIES` in `core/src/surface.rs`, gated once in `pack_key` so the live scan and the manifest share it. Never offered as added packs, never absorbed, never written by a switch; stale `ignored_packs` entries for them are dropped on their own.
- **Absorb self-heals an interrupted write (field incident 2026-09-02):** a switch killed mid-copy (a `tauri dev` rebuild restart, a crash, a power loss) left `execs-viewmodels.vpk.execs-part` and no vpk; the prompt showed the leftover as an added pack next to a Steam verify's `readme.txt` / `workshop`, and Keep then recorded the real pack as ignored — the app said "built" while the game had none. Before it computes the delta, absorb rewrites every manifest file that is missing live and whose library copy exists when either a `<path>.execs-part` sibling is there (our own interrupted write) or the pack is app-owned (`execs-*` — the user manages those through the app, not by deleting files), deletes stray side files under `tf/custom` and `tf/cfg`, and takes repaired keys off `ignored_packs`. `AbsorbOwnedResult.repaired` names what came back. A pack the user brought in themselves and deleted themselves is a real deletion.
- The pack prompt answers three ways: **Update** (adopt the live tree), **Restore removed** (rewrite the removed packs from the library, leaving added packs untouched — shown only when something is missing), **Keep**.
- Steam Cloud stays on. On absorb and on switch, write the same `config.cfg` bytes to `tf/cfg/config.cfg` and `userdata/<id>/440/remote/cfg/config.cfg`. Do not delete Cloud files (Steam redownloads them).
- Progress UI shows real steps (game closed → pack current → remove live packs → write files → Cloud → done), never invented ones. The presenter paces genuinely-reported steps at a minimum display duration (`SWITCH_STEP_MIN_MS`) and fills a step-driven bar so a milliseconds-fast switch still reads as a sequence; no percentages, no steps marked done before their event.

## First run and new profiles
- Find TF2 by scanning Steam libraries (registry, `libraryfolders.vdf`, `~/.local/share/Steam`, `~/.steam/steam`, Flatpak data dir). Confirm `tf/steam.inf` app `440`. Always offer Browse. Multiple installs → picker. Remember one root; profiles are tied to it. No silent write until the path is confirmed.
- **Existing customization:** first launch only **Save current as…**. Do not install comfig on top until they ask.
- **Unused install:** first launch is the setup wizard.
- **Create new profile** (after they already have one) is when the wizard runs for existing users.
- A new profile is a **fresh TF2**: stock binds from Valve `config_default.cfg`, wizard comfig layer, empty `tf/custom/` except official VPKs they picked. Different profile = different binds.
- **Start from (user decision, 2026-09-01):** Create-new-profile opens with two tiles above the name field. **Current setup** (default when a profile is active) copies the active profile's `tf/cfg/config.cfg` **verbatim** — binds, every archived cvar (audio, `con_enable`, `hud_fastswitch`, advanced options) and the `tf_training_has_prompted_*` / `tf_explanations_*` "already shown" flags — so a new profile is seamless and pops no tutorial dialogs. **Fresh TF2** is Valve's `config_default.cfg`, as if newly installed. Everything else (comfig layer/preset, official addons, HUD, `tf/custom/`) always comes from the wizard picks. The first-run wizard has no active profile to copy, so it shows no tiles and is always Fresh. The old inherit-binds settings checkbox is superseded and removed.
- Do not run the nuclear clean-up (`delete tf/cfg` + `-autoconfig -default +quit`) as a normal switch or create.

## mastercomfig
- Do not rebuild the VPK core, interp research, class-cfg takeover, or comfig.app's bind/weapon-VTF customizer.
- V1 in-app: **our UI** for preset, modules, addons. Fetch **official GitHub Release** VPKs at install/update time. Write `tf/cfg/overrides/` (`modules.cfg`, `setup_hook.cfg`, etc.).
- Credit + link to https://comfig.app and their support/donate. Do not brand as official mastercomfig. Do not bundle a stale VPK in our repo as "ours."
- Extras and the preset guide open **in-app**: `open_embedded_page` builds a dedicated WebviewWindow (`comfig-extras` → https://comfig.app/app/, `comfig-docs` → https://docs.comfig.app/latest/). Remote pages get no Tauri IPC — never add them to a capability. Import `comfig-custom/` if they used it.
- Every other external link goes through `openExternal` (tauri-plugin-opener) — plain `target="_blank"` anchors are silently swallowed by wry on Windows.
- Preset preview images are the real mastercomfig koth_sawmill screenshots (MIT, comfig-app repo) vendored under `src/assets/presets/`, re-encoded 1280×720. Never ship AI-generated preview art.

## V1 settings UI
- **Comfig** — preset, modules, addons. No "packages installed" status text when everything is fine; only problems (not installed / read-only / saving) get a status pill.
- **Binds** — click-to-record for usual actions (movement, jump/duck, medic, use, voice, loadout). No alias/script studio.
- **Gameplay** — FOV, viewmodels, and obvious toggles. First-party; writes overrides. Also mirrors the transparent-viewmodels **addon** as an instant-apply toggle (comfig-layer profiles with packages only; it is an addon VPK, never a cvar or module — nothing is written to `execs_gameplay.cfg` for it).
- **HUD** — hud-db catalog, pinned GitHub zip install (one HUD mounted), schema options for popular HUDs. Users can also import their own HUD from a zip/7z or a folder (`import_hud_archive` / `import_hud_folder`, `hud_tree_from_dir`, id from the file name via `hud_id_from_name`, source `Local`). First-party apply; do not embed TF2HUD.Editor. Catalog is paginated (`HUD_CATALOG_PAGE_SIZE`) and each entry's hud-db screenshots open in an in-app lightbox (video URLs filtered out). **One-click for every host (2026-09-02):** `HudInstallKind` is derived from the `repo` host — `github` (pinned codeload zip), `direct` (Dropbox share links forced to `dl=1`; all 26 are 7z), `gamebanana` (`apiv11/Mod/{id}/DownloadPage`, newest zip/7z by `_tsDateAdded`), `thread` (teamfortress.tv post scraped for its last Dropbox archive link), `none` (ToonHUD's theme builder, Steam groups, dead links → the row opens the author's page). `extract_hud_archive` sniffs magic: zip, 7z (`sevenz-rust`, decompression only, same entry/size caps), RAR refused by name. The lightbox also loads the author's `social.album` in-app when it is a GitHub `blob/…/showcase.md` page (raw markdown image URLs) or a single `i.imgur.com` image; imgur albums need an API client id the app does not ship, so they open in the browser (decision 2026-09-02). Catalog cache is `catalog-v3.json`. **Sorting (2026-09-02):** name / last updated / most downloads / most views. hud-db carries none of these and comfig-api's counters need a build token, so `hud_stats.rs` reads comfig.app's listing pages for "Last updated" (all listed HUDs) and tf2huds.dev's `/hud/<id>/__data.json` (devalue-encoded) for download and view counts (~170 HUDs, matched by `comfigHudsUrl`), cached a day in `stats-v1.json`, never blocking the catalog; HUDs without a number sort last.
- **Crosshair** — default in-game crosshair controls plus the **custom crosshair** builder ("custom crosshairs", not "per-weapon crosshairs"). Sources: first-party shapes, imported PNG, the **parametric designer** (style/size/thickness/gap/dot/outline/shadow/opacity → real 64×64 RGBA, params persisted on the record as `design`), and the **community pack** (Venom Crosshairs, 173 static entries pinned to hbivnm/Venom-Crosshairs-List@2e7036cd, fetched on demand, cached, written into the pack **verbatim** with their own dimensions in the weapon scripts; the 3 animated crossanim_* entries are excluded; credit HbiVnm + community authors). Named library entries live as bytes in the pack itself (manifest stores only name→format); re-apply recovers missing bytes from the pack. The stock live preview renders Valve's REAL sprites decoded from the user's own `tf2_textures_dir.vpk` (`get_stock_crosshair_sprites`, DXT/BGRA decoder in `core/src/vtf_read.rs`), with extracted-geometry SVG as fallback; scale = ×`cl_crosshair_scale`/32; `cl_crosshair_alpha` is stored but the engine draws opaque. Pack colour is **cvar-based**, not baked: textures stay white and apply writes the pack's tint to `cl_crosshair_red/green/blue`, so community VTFs recolour too; weapon overrides offer an "All classes" per-slot mode (picking the base shape clears overrides so the fallback keeps working) and copy-class-to-all fans out to OTHER classes only. Every crosshair is shown as a picture (2026-09-02): the stock file picker is a grid of the decoded Valve sprites, library chips and the weapon-override popover (`CrosshairChoice`, no `<select>`) draw through one `paintCrosshair`, and the community picker fetches all 173 VTFs on open (`fetch_community_crosshair_previews`, 8 workers, ~1.7 MiB, cached by commit — upstream ships no preview images) and tints them with the pane colour. Our VTF writer uses the spec header layout (bumpScale@48, format@52, mips@56 — an older build wrote these 4 bytes early). Default controls keep writing the gameplay override; the builder writes `tf/custom/execs-crosshairs/`.
- **Sounds** (2026-09-02) — hit sound and kill sound. TF2 only plays the canonical `sound/ui/hitsound.wav` / `killsound.wav` (the 2010 `tf_dingaling_*_wav_override` cvars no longer exist; those two names are what the engine exempts from sv_pure on Valve servers), so the pack is exactly `tf/custom/execs-hitsounds/sound/ui/{hitsound,killsound}.wav` (`core/src/hitsound.rs`, manifest `hitsound: { hit, kill }` with name + source). Engine rules: 8/16-bit PCM or 4-bit MS-ADPCM at 11025/22050/44100 Hz, mono or stereo; MP3 renamed to .wav does not play. `prepare_hitsound_wav` passes engine-ready files through verbatim and re-encodes other PCM/float WAVs to 16-bit 44.1 kHz (linear resample, >2 channels folded to stereo); ADPCM at a bad rate and non-WAV containers are refused with the reason. Cvars (`tf_dingalingaling`, `_lasthit`, volumes 0–1, pitch 1–255 at ≤10/≥150 dmg, `_effect`/`_last_effect` 0–8, `_repeat_delay`) ride `execs_gameplay.cfg`; a custom file only plays with effect 0, so picking a built-in effect clears the slot's file. Selection: the nine built-in effects auditioned from the user's own `tf2_sound_misc_dir.vpk` (never redistributed), the community pack (WishingStardust/TF2Hitsounds pinned to f5fea33b, 32 of 33 — `levelup` is 32 728 Hz), and the user's own WAV via the file dialog (prepared once, stashed under app data by a random token, auditioned and installed from there — the frontend never handles a path). Third source: **comfig.app hits** — the pinned `src/ssg/hitsounds.json` from mastercomfig/comfig-app (MIT; 2,272 entries, name + SHA-512), audio fetched on demand from `hits.comfig.app/<hash>.wav` and cached by hash. The sounds are user uploads owned by their uploaders (credit + link, never rehost). Their CDN returns a Cloudflare challenge to empty or bare-library user agents; `net.rs` identifies as `execs/<version> (+https://github.com/rndaom/execs)`, which is sufficient — no browser spoofing. Every comfig file is 4-bit MS-ADPCM: the engine plays it verbatim, the webview cannot, so `preview_wav` (core, clean-room decoder) returns 16-bit PCM for auditioning only. The pane is one searchable, sortable library (search, source pill, sort pill; rows play and assign to Hit/Kill) — no picker sheet. GameBanana deliberately not a sound source. Audio bytes cross the bridge as `tauri::ipc::Response`, never JSON arrays. **Boost** (2026-09-02): the engine caps `tf_dingaling_volume` at 1, so `HitsoundEntry.boost` (0/6/12 dB) re-encodes the file itself louder through a tanh soft clip (`prepare_hitsound_wav_boosted`; ADPCM decoded first); the entry keeps the picked-file `token` / comfig `hash` so a later boost change re-encodes from the source instead of compounding. `sound.cache` next to the pack is deleted on every apply (a stale cache plays the previous file).
- **Viewmodels** — **Yttrium-style only** (user decision 2026-08-31): per-class checkbox groups (64 groups generated from CompVMInstaller's source into `core/src/viewmodel_groups.rs` + `lib/viewmodel-groups.ts`, with two upstream bugs fixed — Wrangler installs, dragons_fury_inspect_end included; hiding any Soldier group force-hides the Original like upstream). Build = fetch Yttrium's `animations.zip` (pinned commit b215a5cd, sha256-verified, cached), rewrite chosen SMDs off-screen (`hide_smd_sequence`, frame counts preserved), compile per class with the install's own studiomdl in staging, pack with our VPK writer, install through the import machinery (`ViewmodelSource::Compiled`, `options.hidden` CSV, `options.mode`). **Two hide modes** (`ViewmodelHideMode`, user request 2026-08-31): `full` moves every bone off-screen, so the weapon *and* the arms vanish — CompVMInstaller's behavior and the default, including for packs built before the option existed; `weapon` rewrites only the `weapon_bone*` / `vm_weapon_bone*` rows, which every class parents to `bip_hand_L`/`bip_hand_R`, so the weapon goes and the hands keep animating (all frames preserved, nodes section untouched). Either way a hidden weapon is also hidden in third person — TF2 shares one c_ model between both views; say so in the UI rather than implying first-person-only. Credit Yttrium; assets are fetched from his repo, never vendored. The Horsey-editor concepts (origin/rotate/keep-visible/static/weapon extras, QC/SMD knobs, `viewmodel_compile_capability`) are REMOVED, not hidden — do not reintroduce without a new product decision. Prebuilt VPK import remains. **Casual preload has one home (user request, 2026-09-02): the Mods pane** — "Preload on launch" (`set_profile_preload`, the shared cfg + launch token for the active profile; a viewmodel record follows the choice) and "Material bypass" (gameinfo). The Viewmodels pane carries no preload switch; builds and imports still turn preload on. Preview (2026-09-02) is CompVMInstaller's own "visual image guide": one 16:9 in-game screenshot per option (weapon out) and one blank per class (hidden), hover an option to see its current state, click to flip it, class tabs reset to the blank — the 73 JPEGs are fetched on demand from the same pinned commit as `animations.zip` (`viewmodel_fetch::fetch_preview_image`, cached by commit, returned as raw bytes via `tauri::ipc::Response`), credited to yttrium/Oblique, never vendored. The group → image table is `lib/viewmodel-previews.ts`; a test asserts every group has one. The wiki renders under `src/assets/viewmodels/` remain only as the browser-preview fallback. File-safe FOV/min stay on Gameplay.
- **Mods** (2026-09-02) — three things on one pane. **Your mods:** `ProfileManifest.mods` records (`core/src/mods.rs`; id, name, source local/gamebanana, pack, size) for packs the user brings in through `import_mod_archive` (multi-select `.vpk`/`.zip`/`.7z`; content root auto-detected under `MOD_CONTENT_ROOTS`, one wrapper folder stripped, loose VPKs inside an archive become separate packs, RAR and multi-part VPKs refused with a message) or `import_mod_folder`; a mod is an ordinary `tf/custom` pack, so switch/export/import/absorb carry it and `remove_mod` is a hash-checked delete. **Browse GameBanana:** `src/gamebanana.rs` against apiv11 (TF2 is game **297**, not 440): `Mod/Index` with `_aFilters[Generic_Game]` and `_sSort` (`Generic_MostDownloaded/MostLiked/MostViewed/LatestModified/Newest`), `Util/Search/Results` filtered to `_sModelName=Mod` (sorted client-side), categories from `Mod/Categories` limited to what fits `tf/custom` (no Maps, GUIs, Decal Tool, Prefabs, Serverside Weapons), download via `Mod/{id}/DownloadPage`, thumbnails from `images.gamebanana.com` (CSP). Listing records carry no download counts (`downloads` is null). Paginated (Previous/Next, `Page N of M`), never infinite scroll. **Mature content is hidden by default** (`_bHasContentRatings`, filtered in our client since the API has no such filter; "Show mature content" switch persisted in localStorage, flagged cards get a Mature badge). **Preloader:** profile mods whose pack holds `particles/*.pcf` are offered as particle sources (`profileParticleMods` on `PreloaderSelection`, `profileParticleSources` on the status payload); materials and models need no patching because the gameinfo bypass plus preload already carry `tf/custom` packs.
- **Files** — raw cfg + `cfglint`. Files are classified by origin (user/app vs engine/HUD/pack/comfig-import): non-user files are read-only and lint **advisory-only** (block findings demote to warns via `advisoryPaths`), so provided content can never lock the user's own saves. `tf/cfg/config.cfg` stays strict-with-exemptions and editable.
- **Launch options** — copy-to-clipboard. Auto-write `localconfig.vdf` only if Steam is already closed. Never force-quit Steam to finish setup. Never store `-autoconfig`, `-default`, `-dxlevel`, or `+quit` on a profile.

## Updates
- The app has an **in-app updater**: GitHub Releases + Tauri updater. Check on launch and via footer **Check for updates**. Show “update available,” they click **Install**. **Later** dismisses for the session. No silent force-replace, no analytics/telemetry.
- Endpoint: `https://github.com/rndaom/execs/releases/latest/download/latest.json` (published, non-prerelease tags only). Artifacts are signed in CI with the updater key; the public key lives in `apps/desktop/src-tauri/tauri.conf.json`. Never commit the private key.
- Linux updates are AppImage. `.deb` is first-install only. Windows uses NSIS (`installMode: passive`). No macOS.
- mastercomfig VPK updates are a **separate** control on the Comfig pane (their GitHub releases, not ours).

## Design decisions
- **Design system (2026-09-01)** — one system, defined in `apps/desktop/src/index.css` `@theme`; no hardcoded hex anywhere else. Three surfaces: bg `#121212` → panel `#181818` → panel-raised `#1F1F1F`. Two hairlines expressed as ink alpha so they read the same on every surface: `--color-edge` 8%, `--color-edge-strong` 14%. Warm ink `#ECE7DA` / muted / faint.
- **The accent is a budget.** `#CF6A32` is spent on exactly four things — the primary button, the selected option ring, the active nav marker, the wordmark dot. Everything else is ink. Semantic colour (`--color-ok` / `--color-warn` / `--color-error`) carries meaning only; team colours survive only where they name a TF2 team. No TF2-style display face (Big Shoulders removed 2026-08-30).
- **Type scale** — Inter only, six steps as utility classes: `.t-pane` 28/600, `.t-section` 17/600, `.t-row` 15/500, body 14/400 at 1.55, `.t-meta` 12.5/400 muted, `.eyebrow` 11/500 uppercase 0.12em — the only uppercase in the product. `.tnum` on numeric readouts. Copy is sentence case; buttons say what happens.
- **Spacing** — 4px base, 880px content column, 40px gutters, 48px between sections, 44px minimum row height.
- De-carded layout: pages are flat sections separated by hairlines (`.section`); rows use dividers, not per-row boxes. Boxes are reserved for real surfaces (`.surface`: editors, previews, media), overlays (`.overlay`: popover, progress, prompts), and selectable option tiles (`.tile` / `OptionTile`) whose selected state is a 1.5px accent ring plus a small check — never a fill. `.badge` is sentence case with a hairline ring, filled only when semantic. Buttons are `.btn`/`.btn-primary`/`.btn-ghost` (rounded-lg); `rounded-pill` is for badges and toggle knobs only.
- **Hero-row rule** — every settings pane opens with `PaneHeader` (28px title, one-line lede) then a `.hero-row`: the one decision that matters on the left, a fixed 360px `.surface` preview on the right that stacks under the choices below 1100px and never becomes a full-width banner. Secondary depth folds into a `Disclosure` (closed by default, state remembered per pane in localStorage).
- **Onboarding** — FinderPanel, FirstRunExisting and SetupWizard all render through `OnboardingFrame` (wordmark, eyebrow, balanced title, lede ≤62ch, 640px column; 880px for the wizard) so the three screens are one family.
- **One lock indicator** — while TF2 runs, the top `WriteLockBanner` is the only place that says so. No per-pane pill, no sidebar box; the disabled controls carry the rest.
- **Motion budget** — 150ms ease on colour, opacity and ring; movement (a pane or picture arriving, a disclosure opening, a modal) uses `--motion-move` 220ms with `--ease-out` via `.enter-fade` / `.overlay-enter` / `.scrim`; buttons press to 0.985; nothing at all under `prefers-reduced-motion`.
- **Fewer controls (user feedback, 2026-09-02)** — no cards where a row will do, no `<select>` where a picture or a `Segmented` pill will do, no check marks (a selected tile is a ring, a 6% accent wash and an 8px dot), no native checkboxes (switch rows), no inner scroll boxes on a page that can scroll. Sliders are `.range` (ink thumb; only the crosshair RGB sliders keep team-coloured thumbs). Anything that is a picture (crosshairs, HUDs, viewmodels) is chosen by looking at it (`.thumb` grids).
- Not affiliated with Valve / Steam. Credit mastercomfig where we use it. The desktop not-affiliated disclaimer exists: the App footer carries the full Valve/Steam line (short form when cramped) and the onboarding surfaces (setup wizard, Comfig pane) carry the mastercomfig/comfig.app one.
- TF2 root is remembered only after Confirm. Settings live at Windows `%AppData%\execs\settings.json` and Linux `~/.local/share/execs/settings.json` (`{ "schema": 1, "tf2Root": "..." }`; a legacy `inheritBinds` key is ignored, not an error). Do not use Tauri's `com.rndaom.execs` app-data dir — puts `profiles/` next to this file.
- Finder: Steam roots (Windows `SteamPath` / `InstallPath`, Linux ticket paths plus `~/.steam/root` and lowercase `steam`) → `libraryfolders.vdf` / `appmanifest_440.acf` → accept only after `tf/steam.inf` app `440`. Multiple installs are a picker. Browse always stays visible. A `tf/` pick normalizes to its parent. A stored root that fails validation is unconfirmed.
- Write lock: process **name** `tf_win64.exe` (Windows) / `tf_linux64` (Linux). `refuse_if_running()` wraps live-surface and profile-library writes. Confirming the TF2 root and toggling inherit-binds are app-data settings writes and stay allowed while the game is open. Do not lock on `steam`, `srcds`, `hl2.exe`, or Proton `tf_win64.exe` on Linux.
- Crash hardening: release builds do **not** use `panic = "abort"` (one background-thread panic must not kill the app); a panic hook logs to `<execs data dir>/logs/panic.log`; the lock poller wraps each tick in `catch_unwind`; heavy commands (save/absorb, crosshair apply, HUD match) run in `spawn_blocking`, never on the main thread; the VPK reader range-reads sibling archives and supports filtered reads (`read_vpk_dir_file_filtered`) so weapon-script loading never materializes gigabytes.

## Conventions
- `.npmrc` `node-linker=hoisted` is required on Windows for this monorepo. Don't remove it.
- Plain `package.json` scripts only (Windows dev machine) — no bash-isms.
- LF line endings enforced via .gitattributes; cfg fixtures must never be CRLF.
- **Preloader untracked entries (2026-09-02):** the `C_OP_RenderSprites::RenderUnsorted … unimplemented sprite renderer` console flood is the engine's `orientation_type 0` path on a system whose material failed to load — not a PCF bug. It came from Square_Series patches whose tracking was lost in the 2026-09-01 baseline reset (61 modified `tf2_misc` entries, no snapshots, materials no longer shipped). `PreloaderStatus.untracked_modified` lists such files, and the pane's **Repair with Steam** (`repair_game_files` → `steam://validate/440` via the opener plugin) polls status until they read as stock, then re-applies the selection that was on screen. There is no other source of stock bytes; do not try to reconstruct them. Snapshots record `pristine` (bytes matched the directory's stock CRC) and a resized VPK judges every entry against that CRC instead of discarding tracking.
- **Launching the real game for verification must not change the user's settings.** Never pass video-mode flags (`-w`, `-h`, `-windowed`, `-noborder`, `-fullscreen`, `-dxlevel`): Source persists the mode it ran with into `HKCU\Software\Valve\Source\tf\Settings` (`ScreenWidth`/`ScreenHeight`/`ScreenWindowed`/`ScreenNoBorder`), so the user's resolution stays changed afterwards — hit for real on 2026-08-31. `-condebug` (writes `tf/console.log`) is fine; `-console` is fine but persists `con_enable "1"` into config.cfg, which then absorbs into the active profile. Launch bare, read `console.log` for evidence, and back up + restore anything a test must change.
