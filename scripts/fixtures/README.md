# Package smoke profile fixture

`package-smoke-v018.json` retains exact parsed export manifests and base64 payloads from the `no-hud` and `single-hud` archives in [the actual v0.1.8 compatibility run](../../docs/design/2026-09-22-overhaul/implementation/profile-management/compatibility-v018/README.md). The tagged exporter is `v0.1.8`, commit `85aaf6bc0dd28f43351d4cb5cdb62502737688d5`; each source archive's SHA-256 is recorded in the JSON. The original manifest entries and payloads were read directly from those ZIPs, and every payload hash was checked during extraction.

These are synthetic user cfg, mod and HUD payloads created by that public core. The VPKs were generated by its actual VPK writer. No Valve or third-party artwork, sounds, player secrets, account data or real profile library is included.

The smoke fixture helper authors the on-disk index, profile IDs/names, confirmed settings and disposable TF2 root. Those structures are deliberately distinguished from the tagged-export bytes. It supplies one active profile and one inactive HUD profile, with ordinary mod records, launch options and a shared base VPK. Old and current core readers/exporters independently validated both seeded profiles on Windows; see [package-smoke evidence](../../docs/design/2026-09-22-overhaul/implementation/package-smoke/README.md).

Installer smoke has no runtime dependency on design documentation. This small first-class fixture keeps the release script's inputs available when documentation evidence is excluded from a checkout. It refuses to run unless the fixture exporter tag matches the immediately previous public version derived from changelog history. Refresh the fixture from actual exports of that version for a later release; do not simply change the tag string or reuse older bytes while calling them a newer export. Preserve archive hashes, payload hashes and the distinction between exported and authored structures.
